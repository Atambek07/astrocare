# NASA Data Pipeline

**Status:** Implemented and bundled with verified OSDR evidence.

---

## 1. Pipeline stages

```text
NASA Discovery
  ↓
Metadata Inspection
  ↓
File Download
  ↓
Checksum Verification
  ↓
Parsing
  ↓
Normalization
  ↓
Quality Control
  ↓
Feature Extraction
  ↓
Evidence Registry
  ↓
Simulation Calibration
```

The implementation lives in:

```text
data_pipeline/
```

Processed evidence lives in:

```text
data/raw/nasa/
data/manifests/
data/processed/
data/reference/
```

---

## 2. API endpoints used

The pipeline uses the public NASA OSDR endpoints:

```text
https://osdr.nasa.gov/osdr/data/osd/meta/{numeric_id}
https://osdr.nasa.gov/osdr/data/osd/files/{numeric_id}
https://osdr.nasa.gov/osdr/data/search
```

Important implementation note: metadata and file endpoints require the numeric OSDR ID. For example:

- `OSD-569` becomes `569`;
- `/osdr/data/osd/meta/OSD-569` returns zero hits.

## 5. How to rebuild

From the repository root:

```bash
python -m data_pipeline.build_offline_bundle
```

Offline rebuild from existing cache:

```bash
ASTRALIS_OFFLINE_DATA=1 python -m data_pipeline.build_offline_bundle
```

The pipeline preserves original NASA files under `data/raw/nasa/` and records SHA-256 checksums in `data/manifests/download_manifest.json`.

## 6. Provenance classification

- `NASA_REAL`: actual values from NASA/OSDR.
- `NASA_DERIVED`: calculated from NASA records with documented methods.
- `SYNTHETIC`: generated by the simulation engine.

NASA laboratory values are never converted into fabricated continuous HR, HRV, SpO2 or blood pressure telemetry.

---

## 7. Scientific limitation

NASA OSDR provides short-duration biospecimen and laboratory evidence. It does not provide a 180-day continuous astronaut physiological stream. Therefore continuous vitals are generated by the simulation engine and labeled `SYNTHETIC`.
